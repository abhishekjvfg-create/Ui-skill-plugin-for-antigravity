# documentation

## Goal
Leave a reproducible handoff rather than an unexplained pile of files.

## Workflow
1. Document setup, Node version, entry points, commands, expected outputs and third-party prerequisites. Distinguish implemented features from aspirations.

2. Include data models, token definitions, component states and asset provenance. Record test scope and known limitations.

3. Write a checkpoint after bounded work: changed paths, last passing tests, blockers and next actions. Avoid storing personal data or API keys in examples.

## Acceptance / stop condition
A new maintainer can run the output using only the included instructions.

## Evidence to retain
Relevant file paths, exact commands actually run, observed outcomes and unresolved limitations. Ask before destructive changes or external paid operations.
